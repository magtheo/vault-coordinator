## V-065a — Calendars registry + multi-collection reads

**Config** (`config.py`): new `calendars:` list of `{id, collection, display_name, symbol, writable}`. Defaults derived from current setup:

| id | collection | symbol | writable |
|---|---|---|---|
| `time-blocks` | `vault-time-blocks` | ▪ | yes (existing behavior) |
| `personal` | `personal` | ● | yes (**new**, MKCOL-provisioned at startup if missing — reuse `ics_sync` MKCOL code) |
| `sa` | SA replica collection | ○ | **no** |

`radicale:` section keeps url/auth. `radicale.calendar` remains the time-blocks default for back-compat (`/schedule` endpoints unchanged).

**Endpoints**
- `GET /v1/calendars` → `{"calendars": [{id, display_name, symbol, writable}]}` (auth'd).
- `/schedule/range` + `/schedule/today` + today-projection events: fan out via `asyncio.gather` across registry collections, tag each event `calendar_id`, merge-sort by start.

**Wire enrichment** (`_parse_raw_events`): per event add `id` (`cal:{calendar_id}:{uid}` — opaque, stable), `calendar_id`, `description`, `location`, `all_day` (DTSTART;VALUE=DATE), `symbol` (from registry).

**RRULE expansion** — the big correctness item:
- Add `python-dateutil` to requirements; expand occurrences into the queried window.
- Handle: DAILY/WEEKLY (incl. BYDAY)/MONTHLY/YEARLY, EXDATE, RECURRENCE-ID overrides (override wins, master instance suppressed), all-day series.
- Cap expansion per rule (e.g. 366 occurrences in-window) — unbounded rules must not hang a request.
- Event `id` for a non-modified occurrence: `cal:{calendar_id}:{uid}` + recurrence key suffix (e.g. `#{YYYYMMDDTHHMMSS}`) so instances are individually addressable for future instance-edit; v1 edit is **series-level only** (documented limitation).

**Tests**: registry parse/defaults; fan-out merge (mocked httpx); rrule cases (daily, weekly BYDAY, EXDATE, override, all-day, cap); wire shape; today projection picks up SA + personal.

## V-065b — Event CRUD

- `POST /v1/events` — `{request_id, calendar_id, title, start_at, end_at | duration_minutes, all_day?, description?, location?}`. Idempotent: deterministic UID from `request_id` (reuse `_deterministic_uid`) + mutations-ledger replay → `{id, status: "created"|"already_exists"}`. Target calendar not in registry or `writable: false` → **403** (not 422: it's an authz rule).
- `GET /v1/events/{id}` — composite id parse → single fetch → full event.
- `PATCH /v1/events/{id}` — partial `{title?, start_at?, end_at?, description?, location?}`; **read-modify-write**: GET resource, rebuild the VEVENT preserving UID, DTSTAMP bump, and all unrecognized properties (VALARM, attendee props pass through), PUT back. Series-level edit only v1 (occurrence id → edit the master's base fields; instance-level override = deferred, documented).
- `DELETE /v1/events/{id}` — generalizes the existing time-block delete; read-only calendar → 403.
- `/schedule/*` task time-block endpoints: **unchanged** (entity-alias coupling is semantics). Internally share the ICS builder; `X-VAULT-BLOCK-ID` stays time-blocks-only.
- Capability model: per-calendar writability IS the authz; `calendar_event` capability set stays empty (no per-entity caps needed).

**Tests**: CRUD vs mocked Radicale, idempotent replay, read-only 403, composite-id parse, PATCH property preservation, delete of time-block via new path = old path behavior.

## V-065c — Capture interpret: event proposals

- `interpret()` gains `proposed_type: "event"`, triggered by an **explicit prefix keyword** — Norwegian `avtale `, `møte `; English `event `, `meeting ` (deterministic, no LLM, consistent with the routing philosophy: no silent structural guessing — "tannlege tirsdag 12:30" without a prefix stays a task with due_at).
- Parse within the text: existing date machinery + time-of-day (`kl 14`), ranges (`14–16`), duration suffixes (`30m`, `1t`, `1h`, `2 timer`).
- Proposal fields: `{proposed_type: "event", title, start_at, end_at, all_day, location?}` — additive to `CaptureProposal`; old clients ignore it.
- Default target calendar: `personal` (first writable in registry).
- Dateless ("møte dentist kl 12:30") → start today at time; still just a proposal — the user fixes it in the confirm UI.

**Tests**: prefix triggers (no/se/en), kl-range, duration suffix, dateless fallback, task-with-due_at NOT hijacked (no prefix), proposal determinism, `/capture/interpret` wire shape.
